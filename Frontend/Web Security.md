### Web Security: A Factual Overview

Web security is the practice of protecting web applications, servers, and networks from unauthorized access, data theft, and disruption of service. It requires implementing strict protocols at multiple layers of a system to ensure that only authorized users can access specific data and that the system performs exactly as programmed.

Below is a breakdown of the core components required to secure a web environment.

---

### Identity and Access Management

A secure system must accurately determine who is using it and restrict what that person is allowed to do.

* **Proving Identity:** Systems must verify that a user is who they claim to be. This requires enforcing complex passwords and implementing secondary verification methods, such as requiring a temporary code generated by a separate device.
* **Controlling Permissions:** Once a user's identity is verified, the system must strictly define and enforce what that user is allowed to view or change. A standard user account must be technically restricted from accessing the profile data of other users or altering administrative configurations.

### Protecting Data in Transit and Storage

Data is vulnerable both when it is moving across the internet and when it is resting on a server.

* **Data in Transit:** When information travels between a user's computer and a web server, it must be encrypted using secure communication protocols, primarily HTTPS. Encryption scrambles the data. If the data is intercepted by an unauthorized party during transmission, the intercepted information remains unreadable.
* **Data in Storage:** Sensitive information stored on servers, such as financial records or personal identification, must be encrypted on the disk. Passwords require a distinct mathematical process called hashing. Hashing converts a password into a unique, fixed-length string of characters. This process is intentionally one-way; it cannot be reversed to reveal the original password, ensuring that even if the database is compromised, the passwords remain hidden.

### Validating User Input

A primary source of system vulnerability occurs when an application inherently trusts the data a user submits through forms, URLs, or file uploads.

* **Preventing Database Manipulation:** If input is not strictly checked, a user can type raw database commands into a standard text field. If the application processes that input directly, it will execute the user's commands, allowing them to view, alter, or delete the entire database.
* **Preventing Script Execution:** Users may also attempt to input malicious scripts into public-facing fields, such as a comment section. If the application displays this input to other visitors without neutralizing the code, the script will execute within the visitors' browsers, potentially extracting their active session data.
* **The Standard Rule:** All incoming data must be validated against a strict list of allowed formats and sanitized to remove executable code before the system processes, stores, or displays it.

### Server and System Configuration

The environment hosting the web application must be maintained to prevent exploitation of known hardware and software flaws.

* **Continuous Updates:** Web applications rely on external code libraries, database software, and server operating systems. When security flaws in these components are discovered and published, attackers utilize automated tools to scan the internet for servers running the outdated versions. Applying security patches immediately is a mandatory operational requirement.
* **Minimal Configuration:** A server should only run the specific services required for the application to function. Unused network ports must be blocked, default administrative accounts and passwords must be removed, and unnecessary diagnostic features or error reporting tools must be disabled to prevent them from leaking system information to the public.
