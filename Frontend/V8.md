### JavaScript V8

V8 is Google's open-source JavaScript and WebAssembly engine, written in C++. It is the underlying execution engine for the Google Chrome browser, the Node.js runtime, and the Deno runtime. Its primary function is to compile JavaScript source code directly into native machine code prior to execution, rather than interpreting it in real-time.

Below is a breakdown of the core components and the sequential execution pipeline of the V8 engine.

---

### The Execution Pipeline

The process of converting readable JavaScript into executable machine code occurs through a strict, multi-stage pipeline managed by specialized internal modules.

**1. Parsing**
When V8 receives JavaScript source code, the Parser analyzes the raw text strings. It converts the code into a series of tokens and constructs an Abstract Syntax Tree (AST). The AST is a tree-like data structure that represents the logical syntax of the code.

**2. Interpretation (Ignition)**
V8 does not immediately compile the entire AST into machine code. Instead, it passes the AST to a component named Ignition. Ignition is an interpreter that translates the AST into bytecode. Bytecode is a low-level, platform-independent instruction set. Ignition executes this bytecode directly. This ensures the application starts running quickly with a minimal memory footprint.

**3. Profiling and Observation**
While Ignition executes the bytecode, V8 continuously monitors the application's behavior. It records specific profiling data, primarily tracking how frequently specific functions are executed and the exact data types being passed into those functions (e.g., noting that a specific addition function consistently receives integers, not strings).

**4. Optimization (TurboFan)**
If V8 identifies a function that is executed repeatedly (termed a "hot" function), it passes that function and its associated profiling data to TurboFan. TurboFan is an optimizing compiler. It uses the profiling data to make strict assumptions about the code and compiles the bytecode into highly optimized native machine code for the specific hardware architecture (e.g., x64, ARM). Future calls to this function bypass the interpreter and execute the machine code directly, significantly reducing execution time.

**5. Deoptimization**
Because JavaScript is a dynamically typed language, the assumptions TurboFan makes can be invalidated. If a function compiled to expect integers suddenly receives a string, the optimized machine code cannot process it. When this occurs, V8 immediately discards the optimized machine code and reverts (deoptimizes) execution back to the Ignition interpreter to handle the new data type safely.

### Memory Management and Garbage Collection

V8 manages the allocation of memory for JavaScript objects and automatically reclaims memory that is no longer in use. This system is known internally as Orinoco.

**Generational Memory Layout**
V8 divides its memory heap into two primary segments based on the lifespan of objects:

* **Young Generation:** This area stores newly created objects. Memory allocation here is fast, and the space is small. Most objects in JavaScript are short-lived and are reclaimed quickly in this space.
* **Old Generation:** If an object survives multiple garbage collection cycles in the Young Generation, it is moved to the Old Generation. This space holds persistent data and is collected less frequently to conserve processing power.

**Concurrent Marking and Sweeping**
To prevent the garbage collector from freezing the execution of the main JavaScript application, V8 utilizes concurrent and parallel processing.

* **Marking:** V8 traverses the object graph starting from the root (global object) to identify which objects are still actively referenced by the application.
* **Sweeping:** V8 identifies the memory blocks occupied by unreferenced objects and adds them to a free list, making the memory available for future allocations.
These operations are primarily distributed across background threads, allowing the main thread to continue executing JavaScript code without prolonged interruptions.
